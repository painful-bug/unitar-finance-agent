# MCP API contract

> Current extension: the live server exposes ten tools. Durable thread, ledger replacement, and shared settings contracts are documented in [`../chat-thread-persistence.md`](../chat-thread-persistence.md).

## Contract boundary

The React application talks directly to the existing MCP server through a same-origin reverse proxy. There is no FastAPI application, REST translation layer, or OpenAPI document. The authoritative runtime schemas remain those generated by the MCP SDK from the Python annotations and Pydantic return models in `build_server` ([`src/finance_agent/server.py:130-171`](../../src/finance_agent/server.py#L130-L171)).

The browser client maintains local TypeScript mirrors of the domain types. Contract tests compare discovery and representative structured results with the MCP server. The client must still validate that `structuredContent` is an object with the required top-level fields because MCP exposes it as unknown data at the TypeScript boundary.

## Transport surface

| Method and path | Purpose | Request/response | Streaming | Failure surface |
|---|---|---|---|---|
| `POST /mcp` | MCP initialization, discovery, client notifications, and tool calls | MCP JSON-RPC envelopes; tool results contain `structuredContent` | The current server uses `json_response=False`; execution milestones stream before the complete answer | JSON-RPC error, `CallToolResult.isError`, invalid structured content, Nginx `502`, network timeout |
| `GET /mcp` | MCP server-to-client transport channel when opened by the SDK | MCP event stream controlled by the SDK | Protocol events and execution milestones; no chat-token events are produced | Invalid/expired MCP transport session or upstream failure |
| `DELETE /mcp` | Terminate an MCP transport session | MCP transport termination | No | Invalid/expired transport session or upstream failure |
| `GET /` | Load the React application | HTML | No | Nginx error |
| `GET /assets/*` | Load versioned frontend assets | Static CSS/JS/media | No | `404` or Nginx error |

The Python server binds `/mcp` with Streamable HTTP and event-stream responses ([`src/finance_agent/server.py:177-184`](../../src/finance_agent/server.py#L177-L184)). Nginx must forward `POST`, `GET`, and `DELETE`, preserve MCP response headers, disable proxy buffering, and allow long reads. The browser always uses the same-origin URL `/mcp`; only the UI container sees `MCP_UPSTREAM`.

## Tool contracts

### `parse_budget_rules`

Purpose: compile one or more natural-language monthly rules into validated reusable expressions ([`src/finance_agent/server.py:138-144`](../../src/finance_agent/server.py#L138-L144)).

```ts
interface ParseBudgetRulesInput {
  rules_text: string;
  csv_text?: string | null;
}

type ParseBudgetRulesOutput = BudgetRulePreview;
```

Rules text is required, must contain non-whitespace content, and is limited to 10,000 characters ([`src/finance_agent/budget.py:223-231`](../../src/finance_agent/budget.py#L223-L231)). The server resolves categories from bundled and saved ledgers, adding a validated staged CSV when supplied ([`src/finance_agent/server.py:76-87`](../../src/finance_agent/server.py#L76-L87)). Unsupported compiled rules are returned in the preview with warnings instead of being guessed ([`src/finance_agent/budget.py:299-347`](../../src/finance_agent/budget.py#L299-L347)).

### `create_finance_session`

Purpose: create an unsaved finance-session draft from bundled or uploaded ledger data. The first submitted question persists the chat; later ledger replacements preserve the transcript and reset model context.

```ts
interface CreateFinanceSessionInput {
  csv_text?: string | null;
  as_of_date?: string | null; // ISO YYYY-MM-DD
  context_mode?: ContextMode; // omitted: inherit shared settings
  compaction_turns?: number; // inherit shared settings; integer 5-100
  budget_rules?: BudgetRule[] | null;
}

type CreateFinanceSessionOutput = SessionInfo;
```

When no CSV is supplied, the server uses the bundled ledger and default as-of date `2026-08-15`. For uploaded data without an override, it uses the maximum transaction date ([`src/finance_agent/server.py:50-74`](../../src/finance_agent/server.py#L50-L74)). Omitting configuration inherits backend settings; supplying legacy configuration arguments updates shared settings. Initially the backend uses the three built-in rules ([`src/finance_agent/finance.py:94-104`](../../src/finance_agent/finance.py#L94-L104)).

CSV validation remains exclusively authoritative on the server: maximum 10 MB, maximum 50,000 data rows, required `date`, `kind`, `category`, and `amount` columns, positive amounts, and row-numbered validation errors ([`src/finance_agent/finance.py:13-15`](../../src/finance_agent/finance.py#L13-L15), [`src/finance_agent/finance.py:60-91`](../../src/finance_agent/finance.py#L60-L91)).

### `ask_finance_agent`

Purpose: ask the unchanged agent a question inside an existing session ([`src/finance_agent/server.py:156-164`](../../src/finance_agent/server.py#L156-L164)).

```ts
interface AskFinanceAgentInput {
  session_id: string;
  question: string;
  context_mode?: ContextMode | null;
  include_context?: boolean; // default: false
  compaction_turns?: number | null; // integer 5-100; updates shared settings
}

type AskFinanceAgentOutput = AgentResult;
```

Supplying legacy `context_mode` or `compaction_turns` updates shared settings before the request runs. Every answer captures the current shared configuration once; changes made during execution affect later answers. The turn threshold defaults to 15 and accepts integers from 5 through 100. `include_context` controls whether full before/after message lists are copied into the report; token counts, strategy, decisions, and fallback information remain part of `ContextReport`.

An unknown or closed finance session returns a valid `AgentResult` with `status="error"`, not a protocol failure ([`src/finance_agent/server.py:96-103`](../../src/finance_agent/server.py#L96-L103)). Provider setup and provider-call failures likewise return typed error results ([`src/finance_agent/server.py:106-113`](../../src/finance_agent/server.py#L106-L113), [`src/finance_agent/agent.py:212-221`](../../src/finance_agent/agent.py#L212-L221)). Context failure returns `status="context_error"`, and exhausting the shared step limit returns `status="max_steps"` ([`src/finance_agent/agent.py:204-210`](../../src/finance_agent/agent.py#L204-L210), [`src/finance_agent/agent.py:240-246`](../../src/finance_agent/agent.py#L240-L246)).

### `close_finance_session`

Purpose: evict an active finance session and its lock without deleting its persisted chat record.

```ts
interface CloseFinanceSessionInput {
  session_id: string;
}

type CloseFinanceSessionOutput = CloseResult;
```

Calling close for a missing session is valid and returns `closed: false`. The React UI does not close sessions while switching chats; `get_chat_thread` rehydrates an evicted session. The four durable-thread contracts are documented in [`../chat-thread-persistence.md`](../chat-thread-persistence.md).

## MCP client lifecycle

1. Construct one MCP `Client` and one `StreamableHTTPClientTransport` for `new URL("/mcp", window.location.origin)`.
2. Connect once when the application mounts.
3. Call `listTools` and require the ten tools listed in the durable-thread contract.
4. Reuse the connected client for tool calls during the page lifetime.
5. On a transport failure, discard the failed client and reconnect before the next explicit user action.
6. Do not replay or automatically retry any tool call. Session creation, questions, and closure are not guaranteed idempotent.
7. On normal unmount, request MCP transport-session termination and close the client. Do not claim cleanup on browser crash or abrupt tab termination.

The MCP transport session and the application finance session are separate. Closing the transport does not replace the explicit `close_finance_session` tool call.

## Structured result handling

The client wrapper must:

- reject a tool result with `isError=true`;
- collect human-readable text from textual content blocks;
- reject missing or non-object `structuredContent`;
- check the required top-level fields for the expected tool output;
- return the typed value to React only after those checks; and
- never log CSV text, questions, answers, traces, or context messages.

If the text begins with `Unknown tool:`, show the current stale-server guidance telling the user to restart the MCP product. The UI and backend must be restarted together when the discovered tool set changes.

`AgentResult.status` values are application results, not wrapper exceptions. The answer and attached details must still be rendered for `error`, `context_error`, and `max_steps`.

## Error presentation

| Failure | UI behavior |
|---|---|
| MCP connection/discovery fails | Persistent connection banner; disable mutations until a later reconnect attempt |
| Nginx cannot reach MCP | Present an “MCP server unavailable” message; do not retry the tool automatically |
| Tool result has `isError` | Show returned text in the active panel |
| Unknown tool | Show explicit MCP restart guidance |
| Structured content is absent/invalid | Show a contract error and preserve existing client state |
| Session creation fails | Keep the prior UI session/transcript until a replacement succeeds |
| Agent returns typed non-`ok` status | Render its answer and expose status/trace/context details |
| Rule parsing fails | Keep the current editor and previous preview, and show the error |
| Invalid UTF-8 file | Reject before the MCP call and show a file-decoding error |
| Shared settings save fails | Keep the backend configuration unchanged and show the failed save |

## No OpenAPI or code generation

OpenAPI generation is deliberately absent because no REST/FastAPI layer exists. The MCP server's discovered tool schemas are the machine-readable contract, the small `types.ts` file is the compile-time UI contract, and Python/TypeScript integration tests are the drift detector. Adding JSON-schema-to-TypeScript generation can be reconsidered only if the number of tools or contract churn makes the manual mirror measurably unreliable.

## Shared settings tools

`get_app_settings` accepts no arguments and returns:

```ts
interface AppSettings {
  version: 1;
  rules_text: string;
  rules_draft: string;
  budget_rules: BudgetRule[];
  context_mode: ContextMode;
  compaction_turns: number; // strict integer 5-100
  max_agent_steps: number; // strict integer 1-100
}
type UpdateAppSettingsInput = Partial<Omit<AppSettings, "version">> & { reset_rules?: boolean };
```

`update_app_settings` validates and atomically persists partial changes. Rule text is limited to 10,000 characters; rule sets contain 1–50 validated rules with unique IDs. Updating only `rules_draft` leaves confirmed rules unchanged. Activating custom rules sends `rules_text` and `budget_rules` together after preview. `reset_rules: true` restores the built-in rules and draft text. Backend defaults apply when the settings record is absent; browser-local agent settings are ignored.

`update_chat_thread` additionally accepts `csv_text?: string`, `upload_name?: string`, and `use_bundled_data?: boolean`. CSV and bundled-reset inputs are mutually exclusive. Success preserves earlier turns, records the ledger-change boundary, updates automatic dates/counts, and clears canonical model messages. A failed validation/save retains the prior ledger. No raw CSV is returned publicly.

## Evaluation judge setting

`get_app_settings` now returns `evaluation_judge: "auto" | "jev" | "llm"` (default `"auto"`). `update_app_settings` accepts the same optional field and persists it atomically. Old saved settings receive the default during validation. Restart the backend after upgrading so its MCP schema includes this field. This setting is consumed only by the evaluation script; it does not trigger grading of chat replies. The script reads running MCP settings first, with a persisted-host fallback when the default backend is unavailable; an explicit unavailable `--mcp-url` fails. CLI `--judge` takes precedence.
